## Что делает программа

Программа выполянет функцию сервиса отправки уведомлений с помощью двух каналов связи: 
1. С помощью `email`
2. С помощью `push`
При этом корректно обрабатываются пустые сообщения, неверная настройка канала, паника внутри канала

## Как запустить

1. Перейти в каталог hw4/ (в нем хранятся все исходники программы и main)
2. Для запуска программы в командной строке написать 
```bash
go run ./cmd/notify/main.go
```
3. Для запуска тестов в командной строке написать
```bash
go test ./practice
```

Версия `Go` - 1.27.2

## Проверенные случаи

- Успешная отправка
В случае успешной отправки создаются email и push с корректынми настройками и сообщением "Заказ готов" (каждый канал получил сообщение один раз, история каждого содержит одну запись). Ошибок нет - Dispatch возвращает nil

- Пустой текст
В случае отправки email с пустым сообщением происходит следующая цепочка действий:
1. EmailNotifier.Send видит пустое сообщение и возвращает ErrEmptyMessage
2. В Dispatch проверка err != nil проходит и просиходит обертка ошибки и возвращение ее
3. errors.Is возвращает true, в результате печатается сообщение `error: empty message`
4. Запись в email не происходит

- Отсутствующая настройка
В случае отсутствующей настройки цепочка событий аналогична послежовательности в случае пустого текста, только теперь EmailNotifier.Send видит пустую настрйоку и возвращает SendError, оно ловится в main, печатается, при этом запись в push не происходит

- Паника одного канала
В случае паники одного канала происходит следующая цепочка действий:
1. В SafeDispatch передается два канала - broken и push
2. Когда обрабатывается канал broken SafeSend вызывает Send, который вызывает panic, но recover() оборачивает panic в ошибку, которую SafeDispatch сохраняет
3. Push обрабатывается успешно и в него происходит запись 

## Обработка ошибок

1. Отличие Dispatch и SafeDispatch в том, что Dispatch останавливает работу при появлении первой ошибки и не обрабатывает случай с panic, когда SafeDispatch обрабатывает все ошибки по мере их возникновения(даже panic) и продолжает работу
2. errors.Is и errors.As используются в main для вывода ошибок
3. recover находится вокруг отдельного вызова для того, чтобы в случае panic цикл обработки каналов не прерывался, а продолжался
